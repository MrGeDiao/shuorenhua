Claude 席位 SF 通过率比 v2.3.1 r4 低 9.3 个百分点，超过 5 个百分点，按门槛 4 要求给出解释：

1. **口径不可直接比，三个变量同时变了**。用例集从 111 条切片扩到 120 条全量（多 2 条 SF、7 条 SNF）；判官从 DeepSeek 换成 Grok 4.6；v2.3.1 是单席位口径、本轮是双席位交叉。三者任一都会移动 ⚠️ 的判定线。
2. **回退全部落在 ⚠️，没有一条是 ❌ 或保真失败**。Claude 席位 10 条 ⚠️ 逐条看，都是「清理不彻底 / 动作不完整」：残留同族姿态词（B-44 的「系统性升级」）、骨架只做倒装未换中性连接（B-45）、包装句漏清一处（B-51）、FAQ 未先直接回答（B-06）。零编造、零受保护片段漂移、零 scope 越界。Grok 席位 12 条 ⚠️ 同型。
3. **保真侧指标全面持平或更好**：L1 两席位 0（与 v2.3.1 一致）；`hard_metrics` 长文硬下限失败 0、目标下警告 0；protected spans 粗核除 §6 记的一处 L0 形态外零缺失。
4. Grok 无完整历史全量，只报本轮数字，不做对比。

**结论**：这不是保真能力回退，是判官口径与用例集变化叠加下的风格分收紧。真正该看的是本版目标——示例层不再教补造——见 §5。

## 5. 本版目标的直接观测

规格的假设是：旧示例教的是「说人话 = 补具体数字」，与保真合同「不新增事实」矛盾。本轮在几条直接对应的用例上：

- **B-73 / SF-48（动词名词化，status）**：原文「实现了发布耗时的下降」没有任何数字。两席位都还原成「发布耗时降下来了 / 下降了」，都没有顺势具体化成「快了多少」。注意 `SKILL.md` 第 119 行仍写着 `实现了效率的提升 → 快了多少、省了几个人`（本版按规格不动，留给 v2.5.0），本轮两席位均未被它带偏。
- **B-25 / SF-05、B-102 / SF-21（无源引用）**：两席位都把无源论断整条删除或按 `audit-only` 标注，都没有降格成同向泛化断言。对应本版 `structures.md` 第 12 条的改动——✅ 从「补 Stanford 2023 来源」换成 `rewrite-safe` / `audit-only` 两档。
- **B-36 / SF-32、B-96 / SF-42（README intro）**：两席位都只用原文已有的定位，没有补出「专门处理 AI 套话」这类原文没有的能力。对应 `scene-packs.md` README 节 Before 的改动。
- **B-64 / SF-33（release note 缺 changelog）**：两席位都保留版本号并提示补变更项，没有编造性能数据或用户反馈。对应 scene-packs release-note 节新增的那行说明。
- **B-86 / SF-16**：Claude 席位输出「功能堆得再多，竞争力还是看体验细节、执行效率和团队协同」，与本版 `positive-style.md` §4 C 改后的「更像人」档同构。

这些是相关性观测，不是因果证明：本轮是新候选的首轮全量，没有同候选下的改前/改后对照。它们的作用是给 v2.5.0 的减法提供「改造前」快照。

## 6. 运行完整性

36 次模型调用（预算上限 40），其中有效 33 次。三次无效，全部与被测规则无关：

| 失败 | 原因 | 处理 |
|---|---|---|
| B01-15 `claude/rewrite` | 子进程继承 host 托管的 provider 配置（`ANTHROPIC_BASE_URL` 指本地代理、无 token），CLI 报 `Not logged in` | 生成器给 runner 加 `child_env()` 剥掉 host 变量，回落 keychain OAuth；新建 `-r2` 目录重跑，两席位改写均通过 |
| B76-90 `claude/judge` | judge 少输出一行（B-82），runner 的行数断言拒收 —— L0 输出协议 | 按 [benchmark-tiers.md](./benchmark-tiers.md) L0 条款由运行者归一化：原始输出存 `answer-l0-unnormalized.md`，14 条有效判定存 `rows-l0-normalized.json`（其中硬约束 ❌ 0、风格 ❌ 0），B-82 记为该判官未覆盖，不零化内容分、不重跑整批 |
| B91-105 `grok/rewrite` | Grok API 传输错误（`reqwest error stream: Transport error`），无模型输出产生 | 按 HARNESS「失败不在原目录重跑」新建 `-r2` 目录，两席位改写重跑并通过 |

Provenance：16 次 Claude 调用全部 `claude-opus-5` / firstParty / 零工具 / 显式输入逐字一致 / 输出与持久会话一致；16 次 Grok 调用全部 `grok-4.6-build`、指纹 `fp_08d0bc26c22b024e`、零工具，`verify-grok-model.py` 全部通过。

**HARNESS 已知坑销账**：r13 的 Grok 隔离修复（`--tools ''` + `--system-prompt-override`，替代无效的 `--deny '*'`）此前从未实跑验证过。本轮 16 次 Grok 调用全部通过 provenance 校验、零工具事件，该修复可视为已验证。

`hard_metrics.py --run` 全 8 批：长文硬下限失败 0、目标下警告 0；protected spans 粗核仅 B61-75 批 Grok 席位报缺失 6 条——经逐条核对，是该批 Grok 的 no-op 条目只写「保留原文」而未复述原文正文所致，这些片段在同条「命中项」里被逐一列出并声明保护，判定链均为 no-op，属 L0 输出形态，不是内容漂移。前四批与后三批 Grok 的 no-op 条目均复述了原文，属 run-to-run 形态波动。
