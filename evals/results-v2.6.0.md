# v2.6.0 验证记录

**v2.6.0 新增「写平实」：用户明确要求去掉宣传、吹捧语气时，允许降低夸饰、删除口号。** 小测中两个模型的候选在各项上都不比 2.5.1 差。按事前写死的门槛，GPT 全过；Claude 有两项差一点，维护者看完结果后决定发布。主集 123 条没有触发新模式，结果与 2.5.0 基本一致，另查出一条 2.5 以来就有的失败。

## 改了什么

只在 `SKILL.md` 加了一节「用户要求写平实时」，在 `references/examples.md` 加了一个示例，`editing-guide.md` 没动。用户说「别吹」「写平实点」「去掉营销味」这类话时，模式才会打开；只说去 AI 味、改狠一点、去套话，或者这类话只出现在待编辑的材料里，都不打开。

打开后允许两种编辑：
- 只表示程度的夸饰可以降成平常说法，如「完美融合」「极致的效率」「前所未有的速度」。
- 不交代任何内容的口号可以删除，如「无需妥协」。

承诺、可核查的排名与首次、效果幅度、事实撑得住的程度、作者在叙述和论证里的评价、引语和术语照样保留。只许降调，不许加强。

## 小测：写平实

候选、样本、请求、保护清单和判定在调用前冻结。

- 样本：三篇宣传文本，分别是 PaddlePaddle 中文 README 节选、MatrixOne 中文 README 节选（均为 Apache-2.0）、AIWriteX 科技模板（Apache-2.0）；再加一篇维基新闻长文（CC BY 2.5），用来查正常文本会不会被误降。
- 请求：「这篇宣传味太重了，别吹，写平实点。保留原来的段落和结构。」
- 探针：4 条短句，测不该打开时不打开、该打开时打开。
- 模型：claude-opus-5、gpt-6.1-sol，基线 2.5.1 和候选各跑 1 次，共 32 次有效调用。

| 项目 | Claude 基线 → 候选 | GPT 基线 → 候选 |
|---|---|---|
| 宣传样本中 14 处夸饰降掉的比例 | 64% → 93% | 7% → 79% |
| 宣传样本保护项（承诺、首次、数字、术语）丢失 | 0 → 0 | 0 → 0 |
| 新闻长文中叙述评价被降调 | 约 6 处 → 1 处 | 1 处 → 0 |
| 不触发的三条探针 | 守住 | 守住 |

事前门槛是：候选覆盖率至少 60%，并且比基线高 30 个百分点以上；新闻长文误降为 0。Claude 比基线高 29 个百分点，新闻长文里把「便慷慨捐助」改成了「便捐助」，这两项没有达到门槛。

Claude 的 2.5.1 在用户明确要求时本来就会降夸饰，因为 2.5 写了「用户指定的文风优先」，但没有边界，会顺手降掉新闻里的叙述评价。所以这一版对 Claude 主要是加边界，对 GPT 是加能力。这是看完结果后的解释，没有改动事前的数字。

## 主集 123 条

主集请求都是「清理套话和生硬表达」一类，没有一条触发新模式。这一轮用来确认默认行为没有被带坏。

- 改写：候选规则，claude-opus-5，每题一个新会话，123/123 有效，没有协议失败。
- 判分：claude-opus-5-5 按 [编辑质量判据](v2.5/criteria.md) 逐题判。判为 fail、worse 或 review 的 6 条交 gpt-6-astra 独立复核，这 6 条以复核结论为准。

| 项目 | v2.5.0 发布验收 | v2.6.0 候选 |
|---|---:|---:|
| 信息 / 任务硬失败 | 0 / 0 | 1 / 1（B-33） |
| 编辑质量 better / same / worse | 21 / 102 / 0 | 19 / 102 / 2 |
| 正常文本误改 | 0/58 | 0/58 |
| 冻结正向样本有收益 | 5/7 | 5/7 |

两次的判官不同：2.5.0 由 Codex 裁决并经独立复核，这次由 Opus 5.5 判分、Astra 复核。better 的个数差异在判官尺度的误差范围内，不能读成质量下降。

**B-33**：原文「我帮你把这个事情掰扯清楚，先把它彻底掰开说清楚。」候选输出说明删去后没有剩余正文。Opus 5.5 和 Astra 都认为前半句是交付承诺，应该保留，判为失败。2.5.0 的输出几乎相同（「这段只有预告，没有具体内容，删去后没有剩余正文。」），当时裁决为通过并且改善。这条失败是 2.5 以来的已有行为，新规则没有触及；记为已知问题，本版不修。

**B-06**：候选删了「大家都知道」，并在文后加了一段较长的来源提示，其中把「2 小时内恢复」也算作「大家都知道」引出的内容，与原文不符。正文没有丢信息，质量判为 worse。

另外，B-04 和 B-30 是带「打造」「赋能」「闭环」的宣传句，候选原样返回，与 2.5.0 一致：默认模式下宣传口气仍不构成删除许可，只有用户明确要求写平实时才会清理。

## 限制

- 写平实小测每篇只跑一次，样本是 3 篇宣传文本和 1 篇新闻，属于可行性测试，不是大范围验收。
- 这个模式只处理夸饰，不处理黑话。较长文章里黑话清理偏少，仍是已知缺口，见 [#16](https://github.com/MrGeDiao/shuorenhua/issues/16)。
- 紧挨着具体声明的「无缝」，两个模型都常常保留。
- mini 加了对应的一段说明，但没有单独验证。
- 判分由模型完成，不代表人类编辑共识。
