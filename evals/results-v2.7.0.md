# v2.7.0 验证记录

**v2.7.0 新增修订稿模式：用户明确要修订稿或要求彻底清理时，先列改动清单，再交全文，每条都能撤销。** 发版前用当前规则完整测了一次（2026-11-10）：Claude Code（Opus 5.5）事先定的六项标准全过，Codex（GPT-6.1-sol）过了四项，没过的是清单之外有 1 处实质改动、每篇改变原意 2.5 处（线是 1.8，拿不准的全算错）。两个环境确定改错的数量接近，每篇 0.75 处和 0.62 处。数字见「发版前的完整测试」。

这个结果要打三个折扣：每篇只跑了一次；主审和 Claude 是同一家的模型，没有第三方复核；标准前后改过三次，每次都是看过上一轮结果后改的。

这个模式一共试了五轮，下面按时间顺序记。前两轮没过当时定的门槛，第 3 轮的门槛是看过前两轮结果后重新定的，所以不能说成前两轮的门槛通过了。第 3 轮之后，测量环境和三条机械标准改过一次，见「在真实的 Codex 里重新验收」；发版前那次又把两项门槛改成只记录，见「发版前的完整测试」。前四轮里 Claude 的改写用的都是 claude-opus-5，那几轮「Claude 没有通过」是旧模型的结论。

## 改了什么

- 新增 `references/revision.md`：修订稿的规则、格式和撤销方式。
- `SKILL.md` 加一段路由，说明什么时候进入修订稿。默认编辑规则没有其他变化。
- `editing-guide.md`、`examples.md` 不变。不带脚本，修订稿由模型照清单写出来。

## 前两轮（2026-11-05）

第 2 轮的结果：Claude 黑话目标的字面改动 59%（门槛 63%），每篇丢失受保护说法 0.38 处（门槛 0.12），正常长文每千字 3.7 条（门槛 3）。GPT 前两项过了，AI 长文每千字 15.5 条（门槛 15）、正常长文每千字 7.0 条（门槛 3）没过。两个模型都不通过，当时定为不发。

第 3 轮改了这些：第一行先判断黑话多不多，不多就只校对；例子里加了不该动的口语比喻，规则加了「改后要比原文好读」；用户说别猜时不提「猜的」；清单从 JSON 改成人能读的格式，并增加「撤销所有猜的」「全部撤销」「全收」「再过一遍」。

第 3 轮的门槛改成和线上规则比：底线失败不超过线上一半，覆盖不放宽，负担只算要用户拿主意的条目。规则、样本和门槛在调用前冻结，结果出来后没有改。

## 改规则后的 3 篇复测

根据这 31 处失败改了 `references/revision.md`，`SKILL.md` 和默认模式不动：

- 行业里有固定含义的术语和指标不算黑话，用户要求彻底清理时也一样。
- 第二行写 `不动：`，先列出作者的叫法、贯穿全文的对照、引语和后文复述、行业术语，后面原样留下。
- 收紧 `等义`：换回去读能找出第二种理解，或者范围变窄变宽，标 `猜的`。
- 写稿前把清单逐条再过一遍，动了不该动的内容就整条去掉。

## 其他模型的轻量测试

这不是验收，只做程序检查，没有审改得对不对。用的是改规则之前的版本。每家在自己的运行环境里跑，用默认强度，调用时带沙箱和技能隔离：DeepSeek V4.1 Flash（DeepSeek Harness）、Gemini 4 Argon Medium（Antigravity）、Grok 4.7（Grok CLI）。上面 5 篇各跑一次，再测 1 次撤销。
